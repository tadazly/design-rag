# 策划分析工作流

## 模糊查找策划

先按用户原话执行 `drag_retrieve`。结果过窄时，选择最有区分度的一组功能别名、玩法动词、奖励或消耗、界面模块或配置标识符执行一次 `drag_search`，合并而非覆盖已有证据。不要把仅共享通用词的文档当作同一玩法，也不要逐个表名反复全库搜索。

仅在用户明确要求盘点“最近有哪些”这类跨活动问题时，`drag_search.limit` 可提高到 100，`drag_retrieve.maxDocuments` 可提高到 30-50；普通问题保持 10-20 个候选和 3-8 份文档。`maxChunksPerDocument` 上限为 10，单一文档需要更多证据时应按流程、产出、配置等主题拆分请求。总证据仍受 `maxChars` 约束。

## 解释玩法与产出逻辑

按以下维度组织证据：

- 入口与开放条件
- 核心循环和状态流转
- 消耗、次数、概率、保底或阶段规则
- 奖励来源、产出落点和领取约束
- 前后端或配置控制点
- 历史修改与当前有效版本

某一维度无证据时明确缺失，不用同类活动补写成当前活动事实。

## 查功能相关配表

同时检索策划和配表。用策划说明功能意图，用配表证据确认真实表名、字段、引用关系和控制参数。输出时将“必须配置”“按玩法选择”“可能关联但未确认”分组。

## 查询精灵及实体 ID

1. 先确定实体全名、形态和 ID 类型。用户只问“精灵 ID”时，以 `petId` 为主，同时给出 `modelId`；`petClass`、`eggId`、`图纸Id` 和 `图纸碎片Id` 分别标注，不得混称为同一个 ID。进化链或大小形态分行时按精确名称分别核对。
2. 候选发现阶段先用实体全名调用 `drag_search`，使用 `sort="relevance"`、`latestPerFamily=false`，同时保留 `design` 与 `table` 来源。首轮不要加入泛化的“ID”“配置”等词，避免通用字段压过实体名称。
3. 查询新精灵时，优先比较标题匹配的《每周新精灵信息汇总》；再检索当前 `pet` 配置表。前者证明版本规划或 ID 预分配，后者证明当前配置状态，不得将计划记录直接表述为已经上线。
4. 找到候选后锁定 `documentId`，再用“实体全名 + 目标字段名”定向调用 `drag_retrieve`。精灵 ID 未明确类型时，查询词至少包含 `petId modelId`；需要完整技术标识时使用 `petId modelId petClass eggId 图纸Id 图纸碎片Id`。
5. 回答前确认同一条证据同时包含精确实体名称、目标字段表头、同一行字段值、版本或配置状态，以及可回读的文件与 locator。若摘要只展示名称和出处，应对同一 `documentId` 加入字段名重新检索；未投影的列不得解释为字段为空。
6. 仍取不到目标字段时标记“待确认”，不得回退到旧形态、进化前形态或相似名称。多个来源或版本冲突时并列给出，并按“计划分配 / 当前已配置 / 已证实上线”区分证据强度。
7. 输出时先给用户所问的 ID，再列其他容易混淆的 ID 类型、版本状态和 1-2 条关键来源。

## 评估活动复用

1. 找到有效日期最新且相关度足够的候选。
2. 用 `drag_list_versions` 查看同 family 历史版本。
3. 比较入口、循环、资源、奖励、概率或保底、时间控制、UI、服务端与配表依赖。
4. 输出可直接复用的稳定结构、需要替换的活动内容、需要新增的配置或代码，以及仍需策划确认的问题。

“最新”只表示索引证据中的有效日期最新，不等于线上已经发布。
