# 退步定位

答案落后不一定是插件退步。先证明检索结果确实不同，再改代码。

## 1. 找出会话里的实际调用

```
python scripts/replay.py --bank <bank> calls --tag <轮次> --side B --id <题目 id> [--rep 1]
```

按顺序列出会话调用的插件工具和参数，并标出哪些调用的返回里出现了标准答案“原文摘录”中的关键原文。

## 2. 同参重放

```
python scripts/replay.py --bank <bank> call --sides A,B --tool <工具名> --args '<JSON 参数>' --keys '关键原文1|关键原文2'
```

- 用会话里的原参数，在各版本上各调一次，比较返回的片段、定位和关键原文是否出现。
- 两个会话的参数不同时，两组参数都要在两边重放。这样能分清差异来自检索还是来自模型的提问方式。
- 关键原文取标准答案“原文摘录”里足够独特的短句，不要取泛化词。

整个会话一起重放：

```
python scripts/replay.py --bank <bank> session --tag <轮次> --side B --id <题目 id> --sides A,B[,C]
```

逐个调用比较关键原文，最后汇总整个会话。三个及以上版本时，会另外列出“缺 X”，即其他版本都返回、只有 X 没返回的关键原文。

## 3. 判断

| 现象 | 结论 |
|---|---|
| 同参重放时新版本缺了关键原文，旧版本有，而且返回里没有别的段落写着同样内容 | 检索退步，查排序或截断逻辑 |
| 新版本缺了某条关键原文，但同一返回或同一会话里另有段落写着同样内容，答案也答对了 | 边界互换，记录后不算退步 |
| 同参重放结果相同，只是会话提问的参数不同 | 模型随机性，记录后不改代码 |
| 两版都没有关键原文 | 共同缺陷，另开问题，不算本次退步 |

## 4. 修复后验证

- 写一个用虚构内容复现同样结构的单元测试。先确认它在修复前失败，修复后通过。
- 离线回放各轮会话收集到的调用，统计修复前后关键原文的覆盖变化。改善和变差的调用都要逐个看，变差的要能解释。
- 用新构建的版本重放第 2 步的调用，确认关键原文回来了。
- 最后按 ab-protocol 做独立会话复测。重放结果不能代替新会话。
