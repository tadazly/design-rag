# A/B 作答、盲评与结论

## 准备

1. 在 `config.json` 的 `sides` 里登记两个版本：
   - 已发布版本：解出其发布包，用包里自带的二进制。
   - 候选版本：由当前工作树构建。
   - 两边指向同一份只读索引快照。
2. 冒烟：用 `replay.py call` 在两边各调一次检索工具，确认服务能启动、索引一致。
3. 选题并写进轮次说明：
   - 新题全部参加；
   - 旧题用 `bank.py sample --n <数量> --seed <种子>` 抽取，只抽 `active` 的题；
   - 种子用日期等可复现的值。

## 作答

```
python scripts/run_ab.py --bank <bank> --tag <轮次> --sides A,B --ids <id,...> --purpose "<目的>" [--reps 1] [--parallel 2]
```

- 正式运行前先加 `--dry-run`，核对模型、推理强度、沙箱、MCP 服务命令与环境变量，以及答案输出路径。
- 每题、每个版本、每次重复各起一个全新会话。同一题的两个版本并发提交，平衡服务端延迟。
- 会话不读用户配置，也不留存会话记录。它只挂被测插件，在空工作目录的只读沙箱里运行，拿不到题库和标准答案。
- 作答提示要求会话只用插件作答，关键结论先回读引用再下结论，并列出实际调用的工具。
- 会话失败时，先看 `metrics.jsonl` 的 `errors` 和 `stderrTail`：
  - 两边同时因服务端原因失败（路由超时、连接中断），终止本轮的测试进程后，用 `--ids` 只重跑失败的题。失败产物移到 `failed-attempt-<n>/`，不计入结果。
  - 只有一边失败时，要先查清是不是插件的问题，不能直接重跑。
- 已有同名作答文件时脚本拒绝运行，不会覆盖旧结果。
- 会话里的工具报错（例如参数越界）即使会话自行恢复了，也要在结论里写明原因，并说明与被测改动是否有关。

## 盲评

```
python scripts/judge.py --bank <bank> --tag <轮次> --sides A,B [--reps 1]
```

- 默认每对答案按两种顺序各评一次（X/Y 对调），消除展示位置的影响：
  - 分数取两次平均，找准目标要两次都成立；
  - 两次胜方一致才计胜，不一致计平。
- `--single-order` 只评一种顺序，评审调用减半。这时 `summarize.py` 会列出 X 位置的分布；位置明显不平衡时，结论里要注明。
- 第一种顺序的 X/Y 映射由轮次名、题目和重复编号确定，同一轮重评时不变。
- 评审看不到版本名。标准答案没有覆盖的内容，只要不与原文矛盾、不是臆造，就不算错。
- 评审失败的行会写入错误信息。用 `--ids` 只重评这些题，输出到新文件，不覆盖旧结果。

## 单版本复测

只需要确认某个版本有没有引入新缺陷时，可以只跑这一个版本：

```
python scripts/run_ab.py --bank <bank> --tag <轮次> --sides B --ids <id,...> --purpose "<目的>"
python scripts/judge.py --bank <bank> --tag <轮次> --sides B --single
python scripts/summarize.py --bank <bank> --tag <轮次> --sides B
```

- 单评逐题对照标准答案打分，并列出错误和遗漏，没有胜负。
- 对照基线用 `bank.py history --id <题目>` 查历史轮次。只比较作答模型和推理强度相同的轮次；不同模型的历史结果只作参考。
- 新版本答错或遗漏的要点，先用 `replay.py calls` 查会话里的检索是否返回了对应原文：
  - 没返回，而旧版本同参能返回：按缺陷处理；
  - 返回了但模型没用上：对该题追加独立会话（`--reps 2,3`）再下结论，不凭一次作答归因。

## 汇总

```
python scripts/summarize.py --bank <bank> --tag <轮次> --sides A,B
```

输出逐题评分与胜方、合计胜负、找准数、正确性与完整性均值，以及两版的 token、工具调用和耗时对比。

## 下结论

- 先看逐题：新版本落后的题要逐条读 `errors` 和 `missing`，判断是事实错误、遗漏，还是表述差异。
- 落后题要做同参重放（见 diagnosis.md）：
  - 同样的调用在两版返回的证据不同，且缺的正是关键原文：属于检索退步，要修。
  - 证据相同或新版更全：属于模型随机性，写明依据。
- 复测判定“没有引入新缺陷”：
  - 新版本没有出现旧版本没有的事实错误或关键遗漏；
  - 或者出现了，但已证明来自模型随机性。
- 汇报时写明轮次名、版本、模型与推理强度、选题方式（含种子）、逐题结果、效率对比，以及失败重跑的记录。
