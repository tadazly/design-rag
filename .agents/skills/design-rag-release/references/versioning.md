# 版本推断规则

遵循 SemVer，并以最后一个正式 `vX.Y.Z` tag 到当前源码 SHA 的实际用户影响为准。commit 类型只提供线索，最终以 diff、协议和兼容性为准。

## 优先级

1. 用户给出的精确版本合法且大于最新正式版本时，使用该版本。
2. 仓库尚无 tag，且版本矩阵中的当前版本从未发布时，把当前版本作为首个候选，不额外递增。
3. 已有 tag 与当前版本相同或更高时，根据本次变化递增。

## 变化到版本的映射

- `MAJOR`：1.0.0 之后的不兼容 CLI/MCP/config/index 行为，移除或重命名公开接口，无法自动迁移的数据格式变化。
- `MINOR`：向后兼容的新能力、新 MCP tool/CLI 命令、新文件格式、明显 GUI 功能；0.x 阶段的不兼容公开接口变化也提升 minor。
- `PATCH`：修复、性能或可靠性改善、兼容性补丁、依赖/打包修复，以及需要发布的纯文档或 CI 修正。

同时出现多类变化时取最高等级。`BREAKING CHANGE`、`type!:` 和公开协议不兼容优先于 `feat`，`feat` 优先于 `fix/perf`。无法确认是否兼容时标记为待确认，不自行选择较低等级。

## 特殊情况

- `ProtocolVersion` 不随每次产品版本递增；只有线协议或共享数据合同不兼容时才调整。
- Plugin、GUI、Go backend 当前采用同一产品版本，不独立发版。
- 缓存刷新用的 `+codex.*` 不是正式版本，不得进入 tag、archive 或 marketplace。
- 不从 README、日期或 CI run number 推断版本。
- 不允许降级、复用已有 tag、跳号后静默覆盖，或创建 `latest` 这类浮动 tag。

推断结果必须列出：上一正式版本、候选版本、最高影响级别、支撑该级别的文件/行为，以及仍需用户确认的兼容性假设。
